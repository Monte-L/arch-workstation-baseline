# Network Baseline

## Purpose

This document records a sanitized overview of the workstation network configuration.

Raw network outputs are stored locally under `private/raw/` and must not be published.

## Network Management

| Item | Status |
|---|---|
| Network manager | NetworkManager |
| systemd-resolved | Disabled / inactive |
| DNS source | `/etc/resolv.conf` generated by NetworkManager |
| Primary connection type | Wi-Fi |
| Wired interface | Present, currently unavailable |
| Docker bridge | Present |

| Interface | Type | Public Documentation Notes |
|---|---|---|
| `lo` | Loopback | Standard local loopback interface |
| `wlp3s0` | Wi-Fi | Primary active network interface |
| `enp0s31f6` | Ethernet | Present but unavailable during collection |
| `docker0` | Bridge | Docker-created bridge interface |
| `p2p-dev-wlp3s0` | Wi-Fi P2P | Disconnected during collection |

## DNS Handling

DNS is currently managed through NetworkManager.

The file `/etc/resolv.conf` is generated by NetworkManager and contains the active DNS resolver used by the system.

The raw resolver IP address is not documented publicly.

Quad9 usage must be verified separately without publishing raw DNS output.

## Routing

Routing information is stored only in the private raw collection.

Public documentation should avoid exposing:

- local gateway IP address
- public IP address
- VPN endpoint
- private network ranges
- SSID or connection names

## Listening Sockets

Listening TCP/UDP sockets are collected in the private raw network inventory.

Only relevant exposed services should be documented publicly after review.

## Sensitive Information Excluded

The following information must not be published:

- SSID or Wi-Fi connection name
- MAC addresses
- local IP addresses
- public IP addresses
- default gateway
- DNS resolver IPs, unless intentionally documented
- VPN endpoints
- WireGuard peer configuration
- full routing table
- full socket dump

## Current Assessment

The workstation uses NetworkManager for network and DNS management.

The primary network path during collection was Wi-Fi. Docker is installed and provides a local bridge interface.

Further validation is required for:

- VPN routing behavior
- DNS resolver confirmation
- DNS leak checks
- firewall exposure
- listening services
